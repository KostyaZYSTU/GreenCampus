
# Правила командной разработки GreenCampus

## 1. Организация работы с Git

Для хранения исходного кода и контроля версий используется GitHub.

Основная ветка:
- main — стабильное состояние проекта.

Для каждой новой задачи создаётся отдельная ветка от актуальной main.

## 2. Названия веток

Используются следующие правила:

- feature/FR-01-interface — разработка функции.
- fix/BUG-03-points-error — исправление ошибки.
- docs/TASK-12-update-readme — обновление документации.

Название ветки должно содержать идентификатор задачи из таск-трекера.

## 3. Правила коммитов

Каждый коммит должен иметь понятное описание изменений и ссылку на задачу.

Примеры:

feat(FR-01): add initial interface

fix(BUG-03): correct points calculation

docs(TASK-12): update README

При необходимости номер GitHub Issue указывается в описании коммита: Refs #1.

## 4. Pull Request

Изменения в main вносятся через Pull Request.

Порядок работы:

1. Создать задачу в таск-трекере.
2. Создать отдельную ветку.
3. Выполнить изменения.
4. Создать коммит.
5. Открыть Pull Request в main.
6. Указать связанную задачу.
7. Передать изменения на проверку другому участнику команды.
8. После успешной проверки объединить ветки.
9. Удалить использованную рабочую ветку.

## 5. Проверка изменений

Перед объединением необходимо:

- Проверить соответствие изменений задаче.
- Проверить отсутствие критических ошибок.
- Убедиться, что не добавлены конфиденциальные данные.
- Проверить работоспособность изменённых компонентов.
- Получить одобрение другого участника команды.

## 6. Связь с таск-трекером

Для отслеживания разработки используется цепочка:

Требование → Задача → Ветка → Коммит → Pull Request → Результат.

Идентификатор задачи указывается в названии ветки, сообщениях коммитов и описании Pull Request.
